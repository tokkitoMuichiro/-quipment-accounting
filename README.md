# Учёт оборудования AMMIR

Внутренний сервис, в котором видно, у кого какое оборудование, что лежит на производственных базах и что сейчас в ремонте.

Источник правды — это приложение. Excel собирается сам и при необходимости уезжает на Диск Битрикс24: править таблицу руками смысла нет, она перезаписывается.

Сотрудники заходят из портала Битрикс24 — ФИО подтягивается само. Для локальной разработки есть отдельный тестовый вход.

---

## Кому что можно

Смотреть чужие списки и остатки на базах можно всем. Менять и передавать — только своё или свою базу (админ — без этих ограничений).

| Роль | Обычно делает |
|------|----------------|
| **Администратор** | Настраивает роли и людей, правит любые карточки, принимает и передаёт откуда угодно, ставит замечания по заполнению |
| **Мастер** | Ведёт своё оборудование: создаёт, правит, передаёт, меняет состояние |
| **Кладовщик** | Работает со своих баз; с системной базы «Ремонт» отдаёт только назначенный кладовщик или админ |

Права можно уточнять в интерфейсе. Системный сид не затирает ваши настройки — только добавляет недостающие базовые права и следит, чтобы база «Ремонт» существовала.

## Как устроен учёт

**Серийное** — одна штука с заводским номером. Номера у разных единиц могут совпадать; внутри системы каждая позиция со своим id.

**Неномерное** (рукава, трубы и т.п.) — учитывается количеством. При передаче сотруднику можно отдать часть.

### Передачи

- Человеку или на обычную базу — не сразу: позиция остаётся у отправителя со статусом «Ждёт принятия», пока получатель (или кладовщик базы) не нажмёт «Принять». До этого передачу можно отменить.
- На базу «Ремонт» — сразу, без подтверждения. То же при смене состояния на «В ремонте».

Пока позиция ждёт принятия, её нельзя передать ещё раз.

### Ремонт

Состояние «В ремонте» само перекладывает вещь на базу **Ремонт**. Там видно, кто отправил. Если потом поставить «Исправное», позиция **остаётся на ремонте**, пока её явно не передадут дальше.

### Заполнение карточки

Админ может пометить карточку как неверно заполненную и оставить комментарий. Пока метка висит (красный или жёлтый «на проверке»), передавать нельзя — состояние менять можно. Владелец сохраняет правки → карточка уходит на проверку. Админ подтверждает — метка снимается.

### Уведомления

Входящие передачи и замечания по заполнению могут уходить в личку Битрикс (пачками, с небольшой паузой). В боковой панели — переключатель «Уведомления в Битрикс». На портале у приложения нужен scope `im`.

### История и Excel

В журнале — поиск по названию и номеру, фильтр по тому, кто передал, сортировка по дате.

Сводный Excel обновляется примерно через минуту после изменений; скачать можно кнопкой у тех, кому это разрешено.

- **Backend** — NestJS, Prisma, PostgreSQL  
- **Вход** — локальное приложение Битрикс24 (на проде локальный логин выключен)

## Локальный запуск

Нужны Node.js 22+ и Docker (для Postgres).

```bash
docker compose up -d postgres
cp backend/.env.example backend/.env   # Windows: copy backend\.env.example backend\.env
```

В `backend/.env` для разработки удобно оставить:

- `DEV_AUTH=true` — вход по ФИО / тестовым ролям  
- `SEED_DEMO_USERS=true` — демо-пользователи и тестовая «База Север»  
- свой `JWT_SECRET` (не короче 16 символов)

```bash
cd backend
npm install
npx prisma generate
npx prisma migrate deploy
npx prisma db seed
npm run start:dev
```

В другом терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте http://127.0.0.1:5173.

На экране входа будут кнопки: админ, два мастера и кладовщик — так удобно проверить передачи и разные права. Произвольное ФИО тоже можно ввести вручную.

На боевом окружении `DEV_AUTH` и `SEED_DEMO_USERS` должны быть выключены: демо-данные сид не создаст, тестовый вход не покажется.

Проверки API:

```bash
cd backend && npm test
```

## Битрикс24

Локальное приложение на портале:

| | |
|--|--|
| Установка | `https://<ваш-домен>/api/bitrix/install` |
| Открытие | `https://<ваш-домен>/api/bitrix/open` |
| Права | `user`, `disk`, `placement` (+ `im`, если нужны уведомления) |
| Встройка | пункт левого меню / страница приложения |

В окружении приложения: `BITRIX_CLIENT_ID`, `BITRIX_CLIENT_SECRET`, `BITRIX_APPLICATION_TOKEN`, `FRONTEND_URL`, нормальный `JWT_SECRET`. Опционально `BITRIX_TOKEN_KEY` для шифрования токенов портала в базе.

Сотрудников из портала подтягивает администратор со страницы «Сотрудники».

---

## Запуск целиком через Docker

Из корня репозитория, с заполненным `.env`:

```bash
docker compose up -d --build
```

Поднимаются Postgres, API и фронт. Миграции применяются при старте API.
