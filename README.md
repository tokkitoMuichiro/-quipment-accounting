# Учёт оборудования AMMIR

Это рабочая система учёта: кто чем пользуется, что лежит на производственных базах, что ушло в ремонт. Источник правды — это приложение, а не Excel. Сводная таблица собирается сама и при необходимости уезжает на Диск Битрикс24. Старый сайт на FirstVDS не трогаем: новый стек живёт отдельно, на своих портах и поддомене.

## Как этим пользоваться

Любой сотрудник видит чужие списки и остатки на базах — смотреть можно. Менять и передавать — только своё или свою базу.

- **Администратор** видит всё и может всё: карточки, роли, передачи с любой базы, в том числе с «Ремонт», отметку паспортов где угодно.
- **Мастер** работает со своим оборудованием: заводит, передаёт, меняет состояние, отмечает паспорта у того, что закреплено за ним. Если его назначили кладовщиком базы, он ещё и выдаёт с этой базы.
- **Кладовщик** выдаёт оборудование со своих баз. С базы «Ремонт» отдаёт только назначенный кладовщик этой базы или администратор.

### Передачи

- **Сотруднику** — не мгновенно. Позиция остаётся у того, кто передаёт, в статусе **«Ждёт принятия»**, пока получатель не нажмёт **«Принять»** по каждой позиции. До принятия передачу можно **отменить**.
- **На производственную базу** — мгновенно: оборудование сразу переходит на базу.

Серийная единица — всегда 1 шт. с заводским номером (номера **могут совпадать** у разных единиц; уникальность — по внутреннему id). Неномерное (рукава, трубы и т. п.) учитывается количеством; при передаче сотруднику можно указать часть количества, но пока заявка ждёт принятия, позицию нельзя передать повторно.

### Ремонт

Состояние «В ремонте» само перекладывает позицию на системную базу **Ремонт**. На странице этой базы видно **кто отправил** оборудование в ремонт. Если потом поставить «Исправное», вещь **остаётся на ремонте**, пока кладовщик или админ не передаст её дальше.

Паспорта и сертификаты: админ отмечает где угодно, мастер и кладовщик — только у себя / на своей базе.

### История

В журнале передач есть поиск по названию и заводскому номеру, фильтр по сотруднику (кто передал) и сортировка по дате. Статусы: ждёт принятия, выполнена, отменена.

## Локальный запуск

Нужны Node.js 22+ и Docker (Postgres).

```bash
docker compose up -d postgres
copy backend\.env.example backend\.env
cd backend
npm install
npx prisma generate
npx prisma migrate deploy
npx prisma db seed
npm run start:dev
```

В другом терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте http://127.0.0.1:5173 (на Windows надёжнее, чем `localhost`). Локальный вход по ФИО работает, пока в `.env` стоит `DEV_AUTH=true`. Первый человек в пустой базе становится администратором. На сервере этот вход должен быть выключен — и код это дополнительно блокирует в `NODE_ENV=production`.

`JWT_SECRET` обязателен, не короче 16 символов. В продакшене нельзя оставлять значение из примера.

## Роли по умолчанию

Системные роли создаёт сид. Повторный сид **не затирает** права, которые вы уже поменяли в интерфейсе. Он только создаёт роли, если их ещё нет, и следит за базой «Ремонт».

## Битрикс24

Когда будете вешать приложение на портал (ключи сюда не кладём, они живут только в `.env` на сервере):

- обработчик: `https://equipment.example.ru/api/bitrix/open`
- установка: `https://equipment.example.ru/api/bitrix/install`
- права: `user`, `disk`, `placement`
- встройка: пункт меню / страница приложения

В `.env` сервера: `BITRIX_CLIENT_ID`, `BITRIX_CLIENT_SECRET`, `FRONTEND_URL`, `DEV_AUTH=false`, нормальный `JWT_SECRET`.

Excel `Учёт оборудования (авто).xlsx` перезаписывается целиком. Руками его лучше не править. Выгрузка — кнопка «Скачать» у тех, у кого есть право, плюс автосинхрон примерно через минуту после изменений. В таблице есть колонка «Ожидает принятия».

Синхронизация сотрудников из Битрикс — только у администратора (страница «Сотрудники»).

## Выкладка на FirstVDS

1. Поддомен `equipment.ваш-домен.ru` на IP сервера.
2. Каталог вроде `/var/www/equipment` — не каталог старого сайта.
3. Скопируйте `.env.example` в `.env`. Задайте **свой** `JWT_SECRET` (длинная случайная строка) и ключи Битрикс, когда они появятся. `DEV_AUTH=false`.
4. `docker compose up -d --build` — Postgres **5433**, API **3010**, фронт **8080**.
5. Nginx из `deploy/nginx.conf.example`, затем Let's Encrypt. Фрейм Битрикс не режем: CSP `frame-ancestors` как раз для портала.

Конфликт со старым приложением возможен, только если совпадут домен, порт или имя контейнера. Здесь порты другие.

Сид при старте контейнера безопасен: права ролей не откатываются. Миграции накатываются сами.

## Релизы

Теги вида `v1.0.0`. На сервере удобно выкладывать конкретный тег и собирать заново:

```bash
git fetch --tags
git checkout v1.0.0
docker compose up -d --build
```

Ветки: `feature/…`, `fix/…`, `hotfix/…`, `chore/…`.
